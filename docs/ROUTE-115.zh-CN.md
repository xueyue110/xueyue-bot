# 主路线：PT 订阅 → 本地硬链刮削 → 上传 115 库 → STRM → Emby

这是本仓库的默认玩法，也是 MovieClaw 原生支持的形态：**库的根目录放在 115 上（「115 库」）**。
不需要我们写插件，用官方 `cloud-115`（存储后端）+ `p115-library`（STRM）即可。

```text
① 订阅（PT 站搜索 → qBittorrent 下载到 /downloads）
        │
② 监听导入：识别 + 规范化命名 + 硬链接进「本地暂存目录」
        │        （刮削 / 规格 / 字幕信息在本地先做完）
        ▼
③ 上传任务：硬链接文件 → 115 网盘「库主根目录」（SHA1 秒传优先，不中走分片上传）
        │        海报 / NFO / 外挂字幕跟着视频传到同一目录
        ▼
④ 本地释放：核验 SHA1 对上后释放本地字节（做种中的副本保留，做种结束再删）
        │
⑤ p115-library：115 目录 → 本地 STRM 目录（增量同步，图片/NFO/字幕跟随）
        │
⑥ Emby：扫 STRM 目录 → 读同步下来的 NFO/图片（或自己刮 TMDB）→ 302 直链播放
```

## 配置步骤

### 1. 添加 115 账号

设置 → 网盘 → 添加 115 → 扫码（选一个别的工具没用的登录端，例如支付宝小程序）。
这时才装 `cloud-115` 插件并批准权限。

### 2. 建「115 库」（主根在 115）

媒体库 → 新建：

| 字段 | 填什么 |
|---|---|
| 类型 | 电影 / 剧集 |
| 根目录 | 点「＋ 115 网盘目录」，选 115 上的目标文件夹（如 `影视/电影`）——**这个就是主根** |
| 本地暂存目录 | 自动推荐，和下载目录同盘（硬链接不占额外空间） |
| 本地也保留一份 | 默认关（= 上传后释放）；想留备份就打开 |

主根在 115 的含义：**新片入库后自动上传到这里，本地自动腾空**。

### 3. 订阅依旧走 PT

qBittorrent 作为下载器，订阅照常投递。下载完成 → 监听导入 → 硬链接进暂存目录 → 触发本库的上传。

### 4. p115-library 生成 STRM

主根的同一个 115 目录，再映射成 MovieClaw 里的一个「STRM 库」：

1. 新建一个库（如「115-STRM 电影」），根目录选本地目录 `/media/strm/电影`
   （p115-library 只允许写进「已配置为媒体库」的目录，这一步就是给它授权）
2. 侧边栏「115网盘」→ 核心配置：
   - 115 媒体库 cid：选 `影视/电影`
   - 本地 STRM 目录：`/media/strm/电影`
   - 打开「图片/NFO/字幕同步」（默认开）
3. 数据同步 → 全量同步（之后靠增量：115 操作动态触发）

### 5. Emby 接 STRM

Emby → 添加媒体库 → 路径 `/media/strm/电影`、`/media/strm/剧集`。

因为 p115-library 把 `movie.nfo`、`poster.jpg`、分集剧照、外挂字幕都同步到了 STRM 目录，
Emby 直接读本地元数据，不用重复在线刮削（想用在线刮削也行，关掉 NFO 同步即可）。

## 为什么这条路线不需要自研插件

逐项对照过官方插件的能力（源码位置写在表里）：

| 步骤 | 由谁提供 | 证据 |
|---|---|---|
| PT 订阅、qBittorrent 下载 | 主程序 + 随带 `qbittorrent-downloader` | `src/movieclaw_plugins/qbittorrent` |
| 识别、刮削、硬链接进库 | 主程序监听导入 | `services/library/ingest.py` |
| 上传到 115 库、本地释放 | 官方插件 `cloud-115` + 主程序编排 | `plugins/cloud-115/cloud_115/backend.py`（`upload_part`、`rapid_upload_hashes=("sha1",)`）；`services/drives/uploads.py`（主根在网盘的库逐个上传）；`release.py`（`keep_local`/做种门禁） |
| 海报/NFO/字幕跟随上传 | 主程序 | `uploads.py` 的 `_sync_sidecars`、`LibraryCloudSidecar` |
| 115 目录 → STRM | 官方插件 `p115-library` | `plugins/p115-library`（增量同步、图片/NFO/字幕跟随） |
| Emby 扫 STRM | Emby 本身 | 读本地 NFO/图片或在线刮 |

所以本仓库的 `p115-download` 插件在这条路线上是**多余的**：它做的是「订阅直接把磁力投给 115」，
会跳过「本地硬链接 + 本地刮削」这一步，和你要求的流程相反。它保留只当作可选能力
（例如没有 PT 站、只有磁力资源的情况）。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 上传后再也看不到本地文件 | 正常：主根在 115 时上传完成会释放本地；做种中的副本按做种状态延迟删除 |
| 想本地留一份 | 库设置里打开「本地也保留一份」 |
| 上传很慢 | 看任务中心的上传任务；115 秒传不中会走真实分片上传，受带宽与限速影响 |
| STRM 目录写入被拒 | STRM 目录不在任何媒体库里：先按第 4 步建库指向它 |
| Emby 显示无元数据 | 确认 p115-library 的「图片/NFO 同步」开着且同步完成；或让 Emby 自己刮 |
| 115 库和 STRM 库重复出现同一部片 | 两套库各扫各的，属正常；不想在 MovieClaw 里看到 STRM 库，可以把它设成不展示 |

## 和「待刮削目录」方案的关系

- 本页是**主路线**：文件在本地落一次（硬链），刮削在本地做，然后上云。
- 待刮削方案（SETUP 7.6）是给「115 里已有的资源/手动转存的资源」用的，入口是 115 侧，不是订阅。
