# 架构：主路线 + 两条补充链路

## 主路线（默认）

```text
                 ┌──────────────────────── MovieClaw（官方镜像）────────────────────────┐
 PT 站 ──订阅──► │ 搜索 → 投递 qBittorrent → /downloads                               │
                 │        │                                                           │
                 │        ▼                                                           │
                 │  监听导入：识别/命名/硬链接 → 本地暂存目录（刮削在本地先做）        │
                 │        │                                                           │
                 │        ▼                                                           │
                 │  上传任务：硬链接 → 115 库主根（cloud-115：秒传优先/分片上传）      │
                 │        │      海报·NFO·字幕跟随视频同目录                          │
                 │        ▼                                                           │
                 │  核验 SHA1 → 释放本地（做种中保留）                                 │
                 └────────┼───────────────────────────────────────────────────────────┘
                          ▼
                 p115-library（115 目录 → 本地 STRM，增量同步，NFO/图片跟随）
                          │
                          ▼
                 Emby 扫 /media/strm → 读本地 NFO/图片（或在线刮）→ 302 直链播放
```

关键点：**主根在 115 的库 = 新片自动上传 + 本地自动腾空**，这是 MovieClaw 原生能力，
主程序不需要任何改动；115 的协议由官方 `cloud-115` 插件提供。

## 补充链路一：115 转存 / 离线手动加片

「115 转存」页粘分享链接 / 磁力 / ed2k → 转存到 115 → 待刮削目录 →（挂载+监听导入 或 插件轮询）→ 入库 → STRM。

## 补充链路二：订阅直接投 115（可选，需真账号验证）

设置 → 下载器选「115 云下载」（自研插件 p115-download 注册的类型）：订阅命中后磁力/ed2k 直接进 115。
PT 私有种子 115 取不到 peer，PT 订阅仍用 qBittorrent。

## 为什么本仓库不改 MovieClaw 源码

- 上游每天在动，所有扩展走**插件契约**（下载器适配器、存储后端、宿主操作），升级只换镜像 tag；
- 主路线完全由官方插件 + 配置实现，本仓库只提供 compose、文档与一个可选插件。
